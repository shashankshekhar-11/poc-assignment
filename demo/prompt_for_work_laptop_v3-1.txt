LAYOUT — VERTICAL WIZARD (this is the structural change from v2):
Do NOT build a sidebar-nav-plus-swappable-content-panel layout. Instead:
- All 5 steps are rendered as separate white Fiori cards, stacked vertically, one below another, on a SINGLE scrollable page (no sidebar navigation, no `display:none` panel-swapping between steps).
- Each step card has a header row inside it showing: a numbered circle/badge (1-5), the step title, and a status label — "Completed" (green, with a checkmark), "Active" (blue), or "Pending" (gray).
- Step state behavior:
  - Steps not yet reached are COLLAPSED — show only the header row (number, title, "Pending" status), body content hidden, reduced opacity (~0.6).
  - The CURRENT step is EXPANDED — full header plus body content visible, blue accent (e.g., 3px left border in #0070F2 on the card), full opacity.
  - COMPLETED steps stay visible above but can be collapsed to just their header with a green checkmark and "Completed" status (clicking the header again can re-expand to review/edit).
- Each step's body ends with a "Continue" primary button (except step 5, which ends with the Download Excel button instead). Clicking Continue collapses the current step to its completed-header state, expands the next step below it, and smooth-scrolls the page down so the newly expanded step is in view.
- No separate "goTo(step)" panel-switching function — instead, manage an `currentStep` state variable and a render function that updates each step card's expanded/collapsed/status classes accordingly.
- A slim vertical progress rail (small connected dots, one per step, with the same color coding — green/blue/gray) can run down the left edge of the page next to the stacked cards as a visual index (optional, keep it simple, not a full sidebar).
